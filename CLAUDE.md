## Project Overview

**BuenAdoptante** is a pet adoption vetting platform where rescuers can record, search, and share adopter profiles to prevent animals from reaching irresponsible homes. It uses Next.js 15 (App Router) deployed to Cloudflare Pages, with Cloudflare D1 (SQLite) as the database.

## Commands

```bash
# Development
npm run dev               # Start Next.js dev server on port 3000
npm run build             # Production build
npm run lint              # ESLint
npx tsc --noEmit          # TypeScript type check

# Database
npx drizzle-kit generate  # Generate migration from schema changes (after editing src/db/schema.ts)
npx wrangler d1 migrations apply pet-adoption-db-staging --remote   # Apply to staging
npx wrangler d1 migrations apply pet-adoption-db --remote            # Apply to production
npx wrangler d1 execute pet-adoption-db --remote --command "PRAGMA table_info(adopters);"

# E2E Tests
npx playwright test                          # All tests
npx playwright test --project=authed         # Authenticated tests only
npx playwright test --ui                     # Interactive UI mode

# Contract App (separate Vite mini-app)
cd contract-app && npm run dev               # Vite dev server on port 5173
```

## Architecture

### Data Flow

Server Actions in `src/actions/` are the primary way data is read and written — prefer these over API routes for in-app operations. API routes in `src/app/api/` serve external integrations (contract app, import endpoints, auth callbacks).

The canonical database accessor is `src/lib/db.ts`. It wraps Drizzle with a WeakMap cache to reuse instances per D1 binding. Never instantiate Drizzle directly — always call `getDB(env)`.

### Key Directories

- `src/app/` — Next.js App Router pages and API routes
- `src/actions/` — Server Actions (the main business logic layer)
- `src/components/` — React components (client and server)
- `src/db/schema.ts` — Single source of truth for all table definitions
- `src/lib/` — Utilities (audit, email, R2, scoring, tokenizer, Gemini)
- `src/domain/` — Business constants (admin emails, feature flags, ratings)
- `src/i18n/locales/` — EN/ES translation strings
- `content/` — Keystatic CMS content (guide steps, FAQ, contract template)
- `drizzle/` — Migration SQL files (auto-generated by drizzle-kit)
- `contract-app/` — Standalone Vite app for PDF contract signing

### Authentication

NextAuth 5 (beta) with Google OAuth. Auth config splits across `src/auth.ts` (runtime) and `src/auth.config.ts` (providers/callbacks, safe for edge). `src/middleware.ts` gates routes. Admin authorization is checked via `src/config/admins.ts` — a hardcoded list of emails.

Feature flag `REQUIRED_SESSION_VERSION` in `src/domain/constants.ts` forces re-auth on deploys when bumped.

### Duplicate Detection

The unified `findAdopters()` function in `src/actions/findAdopters.ts` handles both search and duplicate detection via a `mode` parameter:
- `discovery` — Full LIKE search with geo-filter and analytics
- `duplicate` — Fast token-index lookup against `duplicate_tokens` table

Tokenization (`src/lib/tokenizer.ts`) normalizes names (NFD), phones, emails, and social handles. Confidence scoring uses Levenshtein distance + token overlap, bucketed into `high`/`medium`/`low`.

### Internationalization

Language switching (EN/ES) is context-based via `src/context/LanguageContext.tsx`. All UI strings live in `src/i18n/locales/en.ts` and `es.ts`. Always add both locales when adding new strings.

### Database Schema

All tables are in `src/db/schema.ts`. Key tables:
- `adopters` — Core profiles; `status` field is a 1–5 rating (1=Dangerous, 5=Excellent); `deletedAt` is soft-delete for merged duplicates
- `adoptions` — Adoption/request records with event types and timeline
- `duplicate_tokens` — Tokenized fields for fast fuzzy matching
- `duplicate_candidates` — Pre-computed pairs with confidence scores
- `adopter_history` — Audit trail of every adopter change

## Deployment

Branch → deploy mapping:
- `master` → `buenadoptante.org` (production)
- `staging` → `staging.verazadoptantes2.pages.dev` (test with OAuth)
- `feature/*` → random preview URL (OAuth does **not** work here)

CI (`.github/workflows/ci.yml`) runs build → tsc → lint → D1 migrations on push to `staging` or `master`. D1 migrations auto-apply via wrangler in CI — no manual step needed for normal deploys.

**Workflow:** feature branch → merge to `staging` → verify → PR to `master`.

## Edge Runtime

The homepage (`src/app/page.tsx`) uses `export const runtime = 'edge'` for fast cold starts. Cloudflare Workers compatibility requires the `async_hooks` webpack alias in `next.config.ts`. Don't add Node.js-only APIs to edge-runtime pages.

## Content Management

Guide content (steps, FAQ, benefits) is managed via Keystatic CMS (`keystatic.config.tsx`). In dev it reads from the `content/` directory directly. In production it reads from GitHub. The `/keystatic` route is the CMS admin UI.
